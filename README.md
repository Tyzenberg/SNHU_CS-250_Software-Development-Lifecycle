Work I did for SNHU CS-250 Software Development Lifecycle

How do I interpret user needs and implement them into a program? How does creating “user stories” help with this?
User Stories capture what the costumer wants to see in the product. Instead of a "product should do this", user stories help the developer really understand and connect with the costumer. It's almost like they actually talked to them. It also helps feel like you are doing something to make somebody's experience better, not just a general task you have to complete, because higher ups wanted you to do it. This should make the developer care more about the product they are building.

How do I approach developing programs? What agile processes do I hope to incorporate into my future development work?
I really liked how Scrum broke it down into objetives. I've used kanban boards before, but never really understood the real point of them. I've come to realize, I think they've just been implemented incorrectly everytime. Take a large product and break it down into smaller chunks. Take those smaller chunks and break them down into tasks for a team to complete. I am going to start doing this on my personal projects, one of the issues I've found, is I'll start working on section of code that has to tie into another section of code, but as I begin to tie it in, I go down the rabbit hole of working on that section of code instead. I'm really starting to see how OOP ties in with Scrum.

What does it mean to be a good team member in software development?
The easy answer is being there to help your teammates when they are struggling, but I'm starting to think this is gaslighting for people that want to control the entire project. A good team member knows when to be there and help the team. If somebody has headphones on and is trying to hammer out code, don't interupt them. If you really need to talk to them, send them a meeting invite/email/text. Give them the opportunity to complete some of their work.
